## What the amendment asked for (verbatim scope)

Change the client entitlement module from an HMAC checksum gate to **Ed25519
signature verification with Web Crypto (`crypto.subtle.verify`, no
dependency)**. Client embeds only the PUBLIC key; the Worker holds the private
key. Payload `{t, exp, id}` → `base64url(payload) + "." + base64url(signature)`.
Store `pro.exp` with the flag, and add `proStatus()` returning
`{active, tier, exp, renewSoon}` (renewSoon when < 5 days left). Tests for
valid lifetime, valid monthly, expired monthly, tampered payload, wrong key,
survives export/import, no free feature changes. Use the TEST keypair fixture
`test/fixtures/pro-test-keys.json`.

## Reading (stated up front, per dispatch rule 4)

Two points needed a decision; both are documented here and in the module header:

1. **Signing input.** The amendment gives the code layout but not the exact
   bytes the signature covers. I chose the JWT-style convention and documented
   it verbatim in `src/rpg/pro.js`: the Ed25519 signature is over the **UTF-8
   bytes of the `base64url(payload)` string** — i.e. the exact segment before
   the `.`. This keeps client verification byte-exact with no JSON
   re-serialization. Claude's Worker must sign the same bytes
   (`crypto.subtle.sign('Ed25519', key, enc(base64url(payload)))`).
2. **Stored shape.** "`pro.exp` stored with the flag" uses dot notation, so the
   profile's `pro` field is now `false` for a free save or an object
   `{ tier: "monthly" | "lifetime", exp }` for a Pro save (lifetime stores
   `exp: 0`). `tier` is stored explicitly (not derived from `exp`) so
   `proStatus().tier` and future semantics stay unambiguous.

  `verifyProCode(code, now)`, `restorePro(profile, code, now)`,
  `proStatus(profile, now)`, `hasPro(profile, now)`, `PRO_RENEW_SOON_SECONDS`

  survives sanitize and anything else coerces to `false`.
- **`src/rpg/backup.js`** — strict import validation now accepts `pro` only as
  `false` or a valid `{tier, exp}` object (rejects booleans/strings/numbers and
  malformed objects), so the entitlement survives export/import without
  letting a tampered shape through.
- **`test/fixtures/pro-test-keys.json`** — the TEST keypair Claude committed to
  `claude/pro-worker` (public + private JWK + SPKI), used by the tests.
